# 0015 資料パネルは、開いた経路で既定の表示を変え、タブをボタンに置き換える

- 状態: 実装済み（作業ツリー。未コミット・未配備）
- 日付と決めた人: 2026-11-19。利用者が、ナレッジのページは抽出テキストを主にして PDF はボタンで開く案と、チャットの出典から開いたときは PDF を優先する案に、「進めて」と決めた
- 置き換える範囲: 資料パネルの「抽出テキスト｜PDF｜関係図」のタブと、「PDF があれば PDF を既定にする」「出典からは抽出テキストで開く」という挙動。PDF.js ビューアの決定（[0014](0014-pdfjs-viewer.md)）は有効

## 背景
- ナレッジのページを主に使うのは、取り込みの結果（抽出・分割）を確かめる運用者。見たいのは、AI が読んだ内容（抽出テキストのチャンク）で、PDF は補助。
- チャットの出典から開くのは、回答の根拠を原本で確かめるとき。原本の見た目（表・図・レイアウト）が残るのは PDF だけで、抽出テキストでは表が照合できないことがある（実 PDF 203 チャンク中 4 件）。
- 以前は逆だった（一覧から開くと PDF、出典から開くと抽出テキスト）。

## 決定
- 既定の表示は抽出テキスト（URL に `view` が無いとき）。PDF が無い資料は、いつも抽出テキスト。
- チャットの出典から開くときは `view=pdf`（根拠のチャンクがあれば PDF 上で強調）。
- タブをやめ、いま開いていない表示へ移るボタン（アイコン＋文字「抽出テキストを見る」「PDFを開く」「関係図を見る」）だけを並べる。関係図は入寮規程だけ。部品は、チャットと資料一覧で共通のまま（画面ごとの分岐は作らない）。
- 「根拠を特定できなかった」の通知は、抽出テキストと PDF の表示のとき、本文の外に出す（関係図では出さない）。

## 結果と限界
- 一般的な RAG 製品の傾向を確かめた範囲: Dify はチャンクを主に見せ（構築者・運用者向け）、引用の確認では原本の該当ページを開いて強調する実装が一般的（標準検索のみ。最新の標準と断定できる情報は無い）。この決定は、使いやすさについての判断。
- 実ブラウザーでの見た目・操作は未確認（テストは jsdom）。
- 戻し方: `DocumentPanel.tsx`・`useDocuments.ts`（`view: 'pdf'`）・CSS の差分を戻す。データ・API には変更がない。
