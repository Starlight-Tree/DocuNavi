## 書き方

- ファイル名は `NNNN-短い英語の題.md`（番号は連番。欠番を詰めない）。
- 項目: **状態**、**日付と決めた人**、**背景**、**決定**、**結果と限界**（確認していないことは「未確認」と書く）、**出典**。
- **状態**は、次の語のどれかで始め、補足は括弧に書く（この表も同じ語を使う）。いまの事実に合わせて直す。確かめた日付は、各 ADR の状態欄に添える（この表では省く）。
  - 提案: 決める前。
  - 決定: 決めたが、コード・設定には入っていない（文書だけの決定を含む）。
  - 実装済み: コードか設定が `main` に入っている。配備・本番への適用は、括弧で別に書く（確かめていなければ「未確認」）。
  - 配備済み: 実装済みのうち、本番へ出したことを確かめたもの。
  - 置き換え済み / 一部置き換え済み: あとの決定が、全部または一部を置き換えた（置き換えた決定の番号を括弧に書く）。置き換える決定の ADR が無く、同じ ADR の「追記」で一部を改めたときも、一部置き換え済みとし、改めた内容と日付を括弧に書く（例: 0001）。
  - 廃止: 決定の対象を取りやめた。記録としては残す。
- 決定を変えるときは、古いファイルを書き換えず、新しいファイルを足して「置き換え」と書く（古い方の状態も「置き換え済み」〔一部だけなら「一部置き換え済み」〕にする）。
- 測定の数字は、質問の数・上位何件・どの構成かを添える（`evals/CLAUDE.md`）。実機で確認していないことを「確認済み」と書かない。
- 秘密・トークン・実キーの値は書かない。
