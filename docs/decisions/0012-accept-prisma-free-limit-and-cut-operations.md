# 0012 Prisma Free の月 200,000 操作の上限は受け入れ、DB 操作は構成で減らす

- 状態: 実装済み。上限に届いた場合の挙動は、2026-11-18 の引き継ぎの記録では本番 API が 503（[roadmap.md](../roadmap.md)。この文書では再確認していない）
- 日付と決めた人: 2026-11-08（上限の受け入れ。利用者）、2026-11-10〜11（削減の実施）

## 背景
本番 DB は Prisma Postgres の Free プラン（月 200,000 operations。1 SQL = 1 operation。課金期間は暦月）。2026-11-08 ごろから 11-12 ごろに約 +158K 増え、残りが約 2.5K になった（2026-11-15 の Console で 197,536 / 200,000。利用者の貼り付け、証拠等級 A）。急増の原因ごとの内訳は記録していない。

## 決定
- 上限に届いたら、次の月まで読み書きが止まる（データは残る）ことを、利用者が受け入れた（2026-11-08）。有料プランへの切り替えと、監視の作り込みはしない。
- 止まらないための手は、構成で減らすことだけにする。
  - 毎時の同期を、週 1 回（日曜 00:00 JST）にした。`docunavi-ingest-queue-every-5min` は一時停止（削除せず、Job とキューも残す）。バックアップも毎日から週 1 回にした（2026-11-10。[pg-backup.md](../pg-backup.md)）。
  - コード: 会話一覧を 1 クエリ、同期で未変更の資料を書き直さない、キーワード検索の資料の写しを 1 クエリで取得、同期・認証・権限確認の操作の削減（2026-11-10〜11。コミットは Git の履歴）。
- 12-01 の課金期間の更新を待つ。それまでは放置する。

## 結果と限界
- 削減の後は、Console の増加が 1 日 0.2K 前後（11/14 の 197.3K → 11/15 の 197.5K。利用者の読み取り）。週次実行 1 回の消費は数百以下と読める（内訳は未測定）。反映前の率との比較は無い。
- Console のグラフの月末予測（約 430K）は、11/8〜11 の急増からの直線外挿で、直近の率と合わない。
- **未確認:** 上限を超えたときの挙動（課金か停止か。料金表で未確認）、止まる範囲に認証が含まれ、画面から使えなくなるか、2026-11-22 の履歴掃除の初回の消費量。
