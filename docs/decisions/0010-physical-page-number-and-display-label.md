# 0010 PDF のページを「通し番号」と「表示ラベル」に分ける

- 状態: 実装済み（コードは `main`。本番の DB には 2026-11-15 に 0002 を適用済み。**Cloud Run・画面・再取り込みは未実施**）
- 日付と決めた人: 2026-11-15（利用者の依頼で、段階 1〜3 を実装）

## 背景
表紙・目次のある PDF では、物理的な何枚目か（通し番号）と、紙面に印刷された番号が食い違う。たとえば本文の最初のページが、通し番号では 3 でも、印刷では「1」になる。
従来は `chunks.page`（通し番号）だけを出典の表示にも使っていたので、表紙・目次を持つ PDF では、利用者が見る番号とずれる。
一方、通し番号は、元の PDF を開くリンク（`#page=N`）と、評価の根拠ページの照合に使っていて、変えられない。

## 決定
- 通し番号 `page`・`page_end`（1 始まり）は、そのまま残す。リンクと照合は、これを使う。
- PDF の `/PageLabels` が決める表示用のラベルを、別の列 `chunks.page_label`・`chunks.page_end_label` に持つ。画面の出典・チャンクの表示だけが、これを使う。
- ラベルが無い PDF・壊れたラベル・空のラベルは `NULL`（表示は通し番号。従来どおり）。取り込みは、ラベルが壊れていても止めない。
- 内容のハッシュにラベルを含めない。同じハッシュのチャンクは、再埋め込みせず、`UPDATE` でラベルだけを埋める（再取り込みで既存の資料にラベルが入る）。
- 列は追加だけで、`NULL` を許す（マイグレーション `db/migrations/0002_chunk_page_labels.sql`）。ラベルを知らないコードは、そのまま動く。
- 画面の表記: 英数字だけのラベルは「p.i」「p.A-1」、「表紙」のような文字のラベルはそのまま。ラベルがあるのに終わりのラベルが無いときは、番号を混ぜず、始まりだけを出す。
- 関係図（`app/relations/`）は、ラベルが数字でないページ（表紙・ローマ数字の目次）を読まない。目次の「第1章 …」を章の見出しと取り違えないため。全ページが除かれるときは、除かない。
- 評価用の入寮規程（`evals/corpora/guides`）に、表紙・目次（ラベル `表紙`・`i`・`1`〜`3`）を足して、通し番号と表示番号が違う実例にした。評価の `evidence_pages` は通し番号（本文の最初の条は 3）。

## 結果と限界
- API は `page_label`・`page_end_label` を足しただけ（[api.md](../api.md)）。古いサーバーの応答・保存済みの古い会話にはラベルが無く、画面は従来どおり通し番号を出す。
- **配備の順序に制約がある。** 検索・取り込みの SQL が新しい列を名指しするので、**マイグレーション 0002 を、Cloud Run のデプロイと取り込みより先に**本番へ適用する。逆だと検索が 503 になる。本番の DB へは、2026-11-15 に利用者の承認を得て `db/migrate.py --apply` で適用した（適用後の計画で、適用待ちが無いことを確認）。Cloud Run の配備と再取り込みは未実施。
- ローカルで確認したこと（2026-11-15）: pytest（3193 件成功、148 件スキップ）、Vitest（564 件）、型検査、ビルド。評価の BM25（質問 68 件、k=5 と k=2）は、返るファイルも件数も変わらなかった。CI は成功（`main` の 3 件のプッシュ）。
- **未確認:**

  - 実ブラウザーでの、出典・チャンクのラベル表示。
  - 表紙の出典を「表紙」と出す表示の見た目。
