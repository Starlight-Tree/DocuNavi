# 0008 資料の分類「対象」「資料種別」を足し、`collection` は保存・認可の単位のまま

- 状態: 実装済み（ローカルのみ。本番の DB・Cloud Run・画面は未適用。画面は UI モックの承認待ち）
- 日付と決めた人: 2026-11-03（利用者）

## 背景
画面の「グループ」（設定資料・店舗案内・規程・取扱説明書）は、実際には資料の種別だった。利用者が知りたいのは「何について」（ザーハード・みなとコーヒー・つばさ大学学生寮・あおば電機 AW-820）で、
質問の範囲もそれで絞りたい。`collection` は R2 の配置と閲覧権限の単位で、`guides` には 2 つの対象が入っている（対象 4 つ・グループ 3 つ）。

## 決定
- **案 A:** `collection` は保存・認可の単位として維持する（R2 の移動・認可の作り替え・再埋め込みはしない）。
- 対象（`target`）と資料種別（`doc_type`）を、別の分類として足す。画面の名前は「対象」「資料種別」、DB・API の名前は `target` / `doc_type`。現時点では 1 資料に 1 対象・1 資料種別。
- 検索は「権限の範囲 ∩ 対象」。対象を選んでも権限は広がらない。一覧・件数は、見える資料のある分類だけ（見えない資料・対象を漏らさない）。
- 既存の `collection` の会話は変換しない。`?collection=` の URL は旧フィルターとして維持し、解除できる表示を出す。`target` と `collection` を同時に指定したら 422（黙って片方を捨てない）。
- 会話が固定するのは対象の識別子だけ（資料集合のスナップショットは持たない）。
- 初期の分類は、利用者が承認した 6 資料の対応表。**本番のバックフィルの実行は、承認していない**（実行は操作ごとに承認を取る）。

## 結果と限界
- 旧版（`target` を知らない）へバックエンドを戻すと、`target` 付きの会話が全資料を探し、保存された `target` も消えることを、一時 Postgres で確かめた。
  新しい画面を止めることと、バックエンドを戻すことを分け、戻してよい条件と「互換版へ戻す」方針を [configuration.md](../configuration.md) に置いた。
- 検索の SQL・キャッシュ・ロール・チャットの端から端までは、一時 Postgres 17 + pgvector で確かめた。**未確認:** 本番、実際の埋め込み（Gemini）での質、旧版の画面との実機での組み合わせ。
- 画面の変更は、`.claude/rules/ui-review.md` に従い、UI モック（`/mock/classification`）の承認のあとに本体へ入れる。
