### 決定（2026-10-26、利用者）

- **B 案を土台にする。** 初期は「すべて」。入力欄の上で検索対象を選び、入力欄の中にも現在の検索対象を表示する（「選ぶ場所」と「確かめる場所」を分ける。送信した質問と回答の出典にも、どの対象かを付ける）。
- 資料タブは、グループ名・説明文・件数のカードを置く。カードの選択は**一覧の絞り込みだけ**で、検索対象は変えない。「このグループに質問」を押したときだけ検索対象を変える。会話があるときは確認を出し、新しい会話にする（元の会話は元の検索対象のまま履歴に残る）。
- 絞り込み結果が空のときは、「すべての資料で聞き直す」を出す。資料 0 点のグループ（準備中）は選べるが、「資料はまだありません」と示す。
- **将来の拡張候補（初版では採用しない）:** Projects / Spaces 型（資料・会話・指示を 1 つの入れ物にまとめる）。理由は、既定の横断検索を残したいこと、会話履歴を 1 本にまとめる現状を大きく変えたくないこと、今回の目的が検索範囲の明示と絞り込みであること。

### 結論（私の見立て。上の決定の前のもの）

- B 案を土台にし、A 案の「グループごとの件数・説明文」を資料タブに取り入れるのがよい。理由: 範囲を入力欄のそばに置く（NN/g）／「すべて」が既定で、会話が 1 つの履歴にまとまる構成は、入れ物ごとに会話を分ける型とは合わない。
- 画像で見た NotebookLM は、「選ぶ場所」（横のパネル）と「確かめる場所」（入力欄の中の選択数）を分けている。B 案の入力欄の上のチップは「選ぶ」と「確かめる」を兼ねる。入力欄の中に「検索対象：店舗案内（1 点）」のような表示を足すと、見落としが減る（NN/g の指摘とも合う。見立て）。
- 両案に共通する欠点: ①絞った結果が空のときに「すべてで聞き直す」操作が無い／②資料タブのグループ選択が、一覧の絞り込みと検索範囲を兼ねるので、一覧を見ただけで範囲が変わり、会話があると確認の帯が出る／③資料 0 点の「準備中」を選べる。
- グループが 8 つ前後を超えると、B 案のチップは溢れる。そのときは、プルダウンなど別の部品を検討する（根拠なし。見立て）。

### 設計判断

- **チャット中心。** 質問して答えを読み、参照資料から右パネルで根拠を確かめる流れを軸にする。ただし、URL に `tab` が無いとき最初に開く画面は、いまも資料一覧（`frontend/src/lib/urlState.ts` の既定）。
- **資料ライブラリーは、検索・絞り込み・テーブル。** 列は、資料名・グループ・状態・ページ数・更新日時（日時が無いものは「記録なし」）。グループの絞り込みは `<select>`。
- **ヒーロー（カルーセル）と大きなグループカードは、標準画面から外した。** 画面はヒーロー画像を取得も表示もしない。画像生成の基盤・API は変えていない（[image-generation-design.md](image-generation-design.md)）。
- **グループへの質問と、既存の権限制御は維持した。** 一覧の「このグループに質問」と、会話があるときの確認（`ScopeConfirm`）は残した。見える資料はサーバーが決める。
- **一覧の絞り込みと、チャットの質問対象は別。** 絞り込みを変えても質問対象は変わらない。一覧には、両方を並べて示す。
- **出典は、回答全体の参照資料として表示する。** 資料名とページの小さなリンクで、抜粋はツールチップ。6 件目以降は「ほか n 件」。API が返す出典は回答全体に対するもので、**文ごとの引用は付けていない**。
- **根拠の確認は、右パネル。** タブは、抽出テキスト → PDF → 関係図（対象の資料だけ）。引用に合う箇所が見つからないときは、その旨をパネルに示す。
- **対象外（既存の API が未対応）:** アップロード、資料ごとの質問（「この資料に質問」）。削除・再試行・設定の操作も、API が無いので画面に無い。

## 2026-11-04 チャットを主画面にする（左サイドバーの開閉・回答対象チップ・資料一覧の整理）

外部の調査はしていない（競合の画面も見ていない）。「最新の資料チャット UI を参考に」という依頼の方針（情報を全部消さず、主要操作と回答対象を明確にする）に沿って、2 案のモック（案 A: 検索・絞り込みを 1 つの帯に統合した資料一覧 / 案 B: 対象のタブ）と、構成のモックを作って選んだ。モックは Claude Design（非公開）。
**ユーザー検証・競合との比較はしていない。** 「最新のトレンド」「検証済み」とは書かない。

- **決定（2026-11-04、利用者）:** 資料一覧は案 A（対象はプルダウン。案 B のタブは採らない）。回答対象は案 B の入力欄の中のチップ「回答対象：○○・○ 件」1 か所。サイドバーの回答対象の表示と、チャットの上の帯（「質問対象」「資料一覧へ」）は無くした。
- **開閉できるのは左のサイドバー**（利用者が明記）。閉じるとチャットが広がり、再表示のボタンが残る。会話・入力途中の文・回答対象・資料一覧の条件は変わらない。右のパネル（資料の詳細）は既存の構成のまま（資料一覧を右パネルにする案は取り下げ）。
- **最初の画面はチャット**（以前は資料一覧。2026-11-03 の「資料一覧がホーム」を置き換えた）。URL に `tab` が無いときはチャット。ロゴもチャットへ戻る。
- **資料一覧:** 長い注記と「現在のチャットの質問対象」を削除。「取り込み済み」の印は出さず、取り込み中・失敗だけを資料名の横に出す。ファイル名は一覧に出さない（同じ題名が重なるときだけ出す。詳細のパネルにはある）。対象を 1 つ選んでいる間は対象の列を出さず、見出しに対象名と件数を出す。「詳細フィルター」は「フィルター」にして、並び替えは常に見える。有効な条件はチップで常に出し、×で外せる。
- **ボタン:** 「全○資料を回答に使う」。押すと回答対象が切り替わり、資料一覧に留まったまま「適用済み」になる。質問は自動で送らない。会話があるときは、これまでどおり確認を出す。
- **アカウント:** 左下のメールアドレスのボタンからメニュー（ログアウト）。**「設定」は入れていない**（設定画面が無いため。モックにはあった）。
- **モックとの違い:** 資料一覧は、モックの行リスト（「開く」ボタン）ではなく、既存のテーブルのまま（資料種別・ページ数・更新日時の列を残した）。「フィルター」は、ポップオーバーではなく、これまでの開閉の欄（有効な条件があるときは開いたまま）。狭い幅（1024px 未満）は、サイドバーを上に積む既存の方式のままで、モックのドロワーにはしていない。
- **確認した:** 型検査、Vitest（494 件）、`npm run test:e2e`（15 件）、1280px と 390px のスクリーンショット（390px は横スクロールが出ないことだけ）。
- **未確認:** 実際の本番での表示、Safari・Firefox、使い込んだときのサイドバーの開閉の感触。Before の画面は撮っていない（利用者が最初に示した資料一覧のスクリーンショットが、変更前）。
