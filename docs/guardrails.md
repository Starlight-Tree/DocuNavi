# ガードレール

ルールベース（LLM を使わない）の入出力チェックです。`app/agents/guardrails.py` にあります。全体の流れでの位置づけは [architecture.md](architecture.md) にあります。

## 入力

指示の上書き、システムプロンプトの開示要求、役割の乗っ取り、チャットテンプレートの偽装を検出すると、LLM とツールを呼ばずに定型文で拒否します。

- 拒否したターンの発言は、履歴から伏せ字に置き換えます。
- 検出は、NFKC 正規化と不可視文字の除去、空白・記号の挿入に対応します。
- 切断などで検査の前に取り消されたターンの発言が未回答のまま残っていても、次のターンの入力検査で拒否対象なら伏せ字に置き換えます
  （拒否した発言の原文が、後続の LLM 入力に出ない）。

## 出力

回答が `SYSTEM_PROMPT` をほぼそのまま含んでいる場合は、定型文に置き換えます。

ストリーミング（`/chat/stream`）では、完成した回答を待てないので、`StreamingOutputGuard` が本文を逐次検査します。

- 漏洩の判定は「正規化後の連続一致が 24 文字以上」です。末尾の正規化後 32 文字（24 + 余白 8）を送らずに残し、連続一致が閾値に達する前に止めます。
- 止めたら LLM の受信をやめ、`guard_output` が全文を検査して定型文に置き換えます（履歴にも漏洩した本文は残りません）。
- 直近の数十文字の窓で見るので、空白や記号を挟んで連続一致を引き延ばす回避は、ストリーミング中には拾えないことがあります
  （完成した回答は、`guard_output` が全文を検査します）。

## 限界

これは典型的な手口を安く弾くためのもので、プロンプトインジェクションを完全に防ぐものではありません。
