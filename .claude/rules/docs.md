# docs/ を触るとき

詳細は [docs/CLAUDE.md](../../docs/CLAUDE.md)。どの文書が何の正本かの表がある。

- 確認していないことを「確認済み」と書かない。測定は、日付・質問の数・回数・証拠等級（A / B / C / 不明）を添える
- 状態や数字には日付を入れる
- 現状を書く文書は、現状に合わせて更新する。完了済みの詳細な経緯と重複した記録は消してよい（経緯は Git の履歴にある）。消す前に、他の文書・コード・`.claude/rules/` からの参照（節名・項目番号）を grep で確かめる。詳細は [docs/CLAUDE.md](../../docs/CLAUDE.md)
- `roadmap.md` に設計の詳細を足さない（順序と状態だけ）。設計・測定は別の文書に置いてリンクする
- 重要な設計判断は、消す前に `docs/decisions/` に 1 件 1 ファイルで残す。変えるときは古い方を書き換えず、新しい決定で置き換える
- 文書を移す・改名するときは、リンクとコード内のパスの参照を全部直す。移した本文は変えない
- 実キー・トークン・接続 URL の値を書かない。コミット前に `scripts/check-sensitive-terms.sh` を使う
- 文書だけの変更はテスト不要。リンク切れは確かめる
