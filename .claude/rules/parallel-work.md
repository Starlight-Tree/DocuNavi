# 並行作業とサブエージェントの使い方

2026-11-19 にユーザーが決めた方針。このリポジトリの中のルールなので、**ホストの Claude Code と開発コンテナの Claude Code の両方**に効く
（ホストの `~/.claude` とコンテナの `~/.claude`〔名前付きボリューム〕は別なので、共通にしたいルールはここに置く）。
権限・フック（gcloud・gh・git のガード、`.env` の拒否）は変えない。この方針は、それらの内側で動く。

## 待ちは、バックグラウンドで

- CI・デプロイ・長いテストの完了待ちは、バックグラウンド（`run_in_background`、`gh run watch --exit-status`）で走らせ、その間に次の独立した作業を進める。前景で待ち続けない。
  結果を見る時点は、ルートの [CLAUDE.md](../../CLAUDE.md) の「Git」の「CI の結果の扱い」のとおり。
- バックグラウンドで進めてよいのは、**結果に依存しない作業**（読み取り調査・別ファイルの実装・文書・草案）だけ。同じ変更への追加コミット、マージ、デプロイ、次のプッシュ、本番の操作は、結果を見てから。
- 失敗しても、自動で直さない。失敗したジョブ・主な行・ログの場所と、直す案を示して、承認を得てから直す。
- バックグラウンドの待ちは 10 分で打ち切られうる。長いときは `gh run view` で確かめ直す。
- **前景の `gh run watch`・待ちループは、フックが止める**（2026-11-19。`.claude/hooks/guard-foreground-wait.py`、テストは `tests/test_guard_foreground_wait.py`）。この規則を前景で破ったのが、きっかけ。理由に出る直し方は、`run_in_background: true` で実行すること。

## サブエージェント（Agent・Workflow の子）は、調べる・下書き・レビューに使う

| 作業 | サブエージェント | 承認 |
|---|---|---|
| 読み取りの調査、コードの探索、ログの収集 | 使ってよい（バックグラウンド） | 不要 |
| ADR・設計・文書の**草案**、レビュー、反証（ソースを読んで確かめる検証） | 使ってよい | 草案の**採用**は、ユーザーの承認 |
| テスト・型検査・lint の実行 | 使ってよい | 不要（書き込みは一時ファイルまで） |
| コードの変更 | 原則、メイン会話。独立していて範囲が限られるときだけ、ファイルの範囲を指定して任せる | 変更の取り込みは、メイン会話が差分を確認する |
| コミット・プッシュ・デプロイ・設定変更 | **任せない**（メイン会話だけ） | CLAUDE.md の「Git」「承認が必要」のとおり |
| 本番の DB・Secret・IAM・課金、`deploy.yml` の起動 | **任せない・指示しない** | 毎回、明示の承認 |

- サブエージェントへの指示に、**してよいこと・してはいけないこと**（書き込み・コミット・プッシュ・本番アクセスをしない、など）と、**返す形**（結論・根拠・未確認の点・リスク）を書く。
  サブエージェントの出力は、取り込む前にメイン会話が確かめる（再現できていない指摘を、事実として扱わない）。
- 同じファイルを触る作業は、並行にしない。並行で書き込ませるなら、ファイルの範囲を分けるか、worktree を分ける。
- 設計の判断・本番に影響する判断・失敗の原因の判断は、サブエージェントに丸投げせず、メイン会話でユーザーと決める。
- サブエージェントも、CLAUDE.md の禁止事項（キーを出さない、ガードを外さない、承認制の操作）に従う。ガードに止められたら、回避せず、報告する。
- 使う数は、作業に見合う数にする（読み取りの調査は多くてよいが、書き込みを伴う並行は少なく）。

## ホストとコンテナで共通のこと

- どちらの Claude Code も、この表のとおりに動く。ホストで承認した操作が、コンテナで自動的に承認されることはなく、その逆もない。
- メモリー（`~/.claude/projects/…/memory/`）はホストとコンテナで別。共通にしたい方針は、メモリーではなく、このリポジトリのルールに置く。

## 使い方の細目（2026-11-19 に、公式の文書と第三者の記事で確かめた。根拠の原文は Git の履歴）

- **既定:** サブエージェントは既定でバックグラウンド。承認の要る操作に当たると、メイン会話に確認が出るので、承認の守り方は変わらない（公式）。
- **ツールを絞る:** 読み取り専用にしたいときは、定義の `tools`（許可リスト）で `Write` `Edit` などを外す。このリポジトリの `.claude/agents/`（`repo-researcher` `docs-reviewer`）がその定義。
  書き込む並行作業は `isolation: worktree` で分けられる。マージが通っても意味の食い違いは残るので、テストと人の確認は省かない。
- **費用:** サブエージェントは自分のトークンを使う。並列・出力の隔離・別の目での確認は得られるが、答えが賢くなるわけではない（公式）。多数・長い結果を返させると、メイン会話の文脈を食う。入れ子は 3 階層まで、同時に 20 まで（公式）。
- **レビューは別の目で:** 書いた本人の文脈を持たないサブエージェントにさせる。「スタイルは除く」と範囲を絞り、再現できない指摘は採らない。
- **守らせたいことは、フックで:** 「必ず守る」は、プロンプトや CLAUDE.md ではなく、決定的なフックで強制し、数は少なく保つ（公式）。フックの追加・変更は、ユーザーの承認を得てから（CLAUDE.md の「承認が必要」）。
- **未確認:** この環境で上の挙動（背景の既定、`isolation`、入れ子の上限）がそのとおりか。`.claude/agents/` の定義が読み込まれて `tools` の制限が効くか、Workflow の子エージェントに効くか（効くと確かめるまでは、指示で「書かない」と伝えるだけ）。
