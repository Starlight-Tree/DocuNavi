# 引き継ぎ（毎回、同じ手順で）

引き継ぎの**中身**（状態・残り・学び）は、メモリー（`~/.claude/projects/<このプロジェクト>/memory/`）に書く。このスキルは**手順**だけ。
作業は、読み取りと、メモリー・後始末だけ。コミット・プッシュ・gcloud の書き込みは、ここでは行わない（未プッシュがあれば報告して、承認を求める）。

## 1. 状態を確認する（読み取りだけ）

- `git fetch` → `git status -sb`、`git log --oneline origin/main..HEAD`。未コミット・未プッシュがあれば、そのまま報告する（勝手に片付けない）。
- 直近のプッシュの CI（`gh run list --limit 3`）。実行中なら、そう書く。
- 承認待ちの項目（プッシュ・実 API・本番・IAM・秘密の再発行など）と、見送られた項目を分ける。見送られた項目は、依頼がない限り「残り」に載せない。
- 自分が起動したもの（サーバー・バックグラウンドのジョブ・Playwright・E2E の 3100/3101/8100 番）が残っていないか。`ss -ltnp` で確かめ、PID を指定して止める（`pkill` の一括は使わない）。

## 2. 消えうる物を、メモリーに写す

- スクラッチパッド（`/tmp/claude-…/scratchpad/`）のスクリプトは、セッションが変わると消えうる。**書き込み系コマンドの引数・手順**は、スクリプトのパスでなく、そのままメモリーに書く。
- 一時ファイル（`.gcloudignore` の差し替えなど）を差し替えたままにしていないか。元に戻っているか（`git status`）。
- 秘密（キー・トークン・接続文字列・Cookie の値）は、メモリーに書かない。

## 3. メモリーを更新する

- 新しい引き継ぎのファイルを `project-handoff-<日付>-<主題>.md` で作る（前のものがあれば、リンクする）。種類は `project`。
- 書く項目: **状態**（push 済みのコミット・CI・本番に出ているか）／**済み**／**残り**（番号つき。承認済みか・誰が実行するか）／**学び**（次に同じ失敗をしないための、非自明なことだけ）。
- `MEMORY.md` の索引の先頭に、1 行を足す。古い引き継ぎの行は、「旧」と書いて残す。
- 古くなった記述（状態が変わったもの）は、直す。コードや Git の履歴から分かることは書かない。

## 4. 報告する

- 状態を 2〜3 行で、続けて「新しいセッションで最初にやること」を 3 つまで。
- 判断を待っている点（ユーザーの決定）と、あなたの実行が要る点を、分けて示す。
- 「完了」とは書かない。完了かどうかは、ユーザーが決める。
